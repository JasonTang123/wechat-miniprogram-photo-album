## 1. 目标（Phase 1）

在最大限度保留后续画质扩展空间的前提下，完成：

1. 开发/索引侧与 NAS 建立稳定可达连接，根路径为 `/Volumes/home/Dudu`。
2. 遍历该根下的**文件夹树**，产出「目录名 + 该节点照片数量（及子树汇总策略，见 §3）」的结构化数据。
3. 微信小程序 **home（主页）** 展示上述目录信息。
4. 小程序内建立与 NAS 一致的**层级映射**：点击进入对应层级，看到该层文件夹与文件条目（本阶段可只显示文件名/类型/数量，**不加载像素**）。
5. **不加载照片**；单独书面探讨「尽量不损画质」的加载策略、WebP 等格式、小程序本地存储限制（§6）。

非目标（本阶段不做）：

- 网格缩略图 / 原图预览 / 保存到系统相册
- 百度网盘接入
- 正式提审与公开搜索上线
- 写回 NAS（默认只读）

## 2. NAS 连接需求

### 2.1 目标状态

| 角色 | 需要能访问 `/Volumes/home/Dudu` 吗？ |
|------|--------------------------------------|
| 本机（开发 / 索引任务） | **必须** |
| 阿里云 ECS 上的相册 API | 若列表由云端提供，则 ECS 也必须有等价挂载或同步副本；若列表由本机服务在家庭网提供，则另议 |
| 微信小程序进程本身 | **禁止直连** SMB/内网 IP 作正式方案；只访问已备案 HTTPS API |

### 2.2 现状勘察（2026-11-08）

本机已存在 SMB 挂载，**无需先为开发强制上 OpenVPN**：

```text
//jt@DS725plus._smb._tcp.local/home on /Volumes/home (smbfs, …)
```

根下已见子目录示例：`一起旅游啦`、`结婚式` 等。  
另有 `//jt@192.168.31.212/Download` → `/Volumes/Download`（电影盘，与本相册根无关）。

### 2.3 连接方案（按优先级）

| 优先级 | 方案 | 适用场景 | 说明 |
|--------|------|----------|------|
| P0 | **局域网 SMB**（现状） | 电脑与群晖同网 | 路径 `/Volumes/home/Dudu`；实现成本最低 |
| P1 | **OpenVPN / WireGuard / 群晖 VPN** | 外出时本机仍要索引/调试 | VPN 起来后仍挂载同一 SMB 路径或映射到相同逻辑根 |
| P2 | **群晖 QuickConnect / 反代 HTTPS** | 仅当必须公网直达 NAS Web API | 证书与备案约束重，不作为 Phase 1 首选 |
| P3 | **云端 ECS 挂载 NAS**（如现有阿里云 NAS `/mnt/nas_download`） | 小程序正式域名已指向 ECS | 若 `Dudu` 相册不在云 NAS，需 **rsync/同步** 或专线；与「家庭 home 盘」是两条存储，需求上要明确是否同步 |

**已决议（见 §0 R1/R2/R5）：**

- Phase 1 索引与开发：**以本机 SMB `/Volumes/home/Dudu` 为权威数据源**。
- OpenVPN：外出可选；**不改变逻辑根**（应用层用 `Dudu/...`，物理前缀可配置）。
- 小程序数据：本机相册索引/API 提供；迁 ECS 为后续，且**不**为此全量同步原图到云 NAS。

### 2.4 连接验收标准

- [ ] `test -d /Volumes/home/Dudu` 为真（或 VPN 连通后为真）。
- [ ] 能列出至少一级子目录（与 Finder/SMB 一致）。
- [ ] 断线可检测；重连后索引任务可恢复（幂等，不要求实时监听 inotify）。

## 3. 目录树遍历与照片计数

### 3.1 功能需求

对根 `Dudu` 做树遍历，输出每个**文件夹节点**的：

| 字段 | 含义 |
|------|------|
| `id` / `path` | 相对根的稳定路径，如 `一起旅游啦/2026.9.25泉州之行`（UTF-8） |
| `name` | 目录显示名 |
| `depth` | 相对根深度 |
| `photo_count_direct` | **本层**直接存放的照片文件数 |
| `photo_count_total` | 本层 + 所有子孙的照片数（**主页必用**，决议 R3） |
| `child_dirs` | 子目录列表（名 + path） |
| `files`（本阶段） | 本层非目录条目的元数据：文件名、扩展名、size、mtime；**不含像素、不含 base64** |

### 3.2 照片文件判定（初稿）

计入「照片」的扩展名（大小写不敏感）：

`jpg / jpeg / png / heic / heif / gif / webp / tif / tiff / bmp / dng / raw / cr2 / nef`

排除：

- 以 `.` 开头的文件/目录（含 `.DS_Store`、`@eaDir`、`#recycle`）
- 明显非图：`mp4/mov/mkv` 等（可另计 `video_count`，本阶段主页可不展示）

### 3.3 性能与空间约束

- **空间优先**：索引结果存轻量 JSON/SQLite，只存路径与计数，不预存缩略图。
- 大目录（如单文件夹 800+ 张）遍历应可分页或后台任务；主页先展示「目录 + 数量」，文件列表按页拉取。
- 不在 Phase 1 为每个文件生成派生图。

### 3.4 勘察样例（仅作需求参照，非冻结数据）

对 `/Volumes/home/Dudu` 浅层抽样（2026-11-08）：

| 相对路径 | 直接照片数 | 子目录数 |
|----------|------------|----------|
| `.`（根） | 0 | 2 |
| `一起旅游啦` | 0 | 9 |
| `一起旅游啦/2025.10.3新疆` | 61 | 0 |
| `一起旅游啦/2026.11.7长隆野生动物园` | 265 | 0 |
| `一起旅游啦/2026.9.25泉州之行` | 804 | 0 |
| `结婚式` | 0 | 2 |
| `结婚式/2023.6.27领证` | 0 | 4 |
| `结婚式/婚纱照` | 0 | 2 |

主页预期：根层展示「一起旅游啦」「结婚式」及各自 `photo_count_total`；点进后再展示下一层。

## 4. 小程序 Home 展示需求

### 4.1 页面

- 路由建议：`pages/home/home`（或将现有 `pages/index` 升级为 home，二选一，设计阶段定）。
- 导航标题：电子相册（可配置）。

### 4.2 主页信息架构

根层卡片/列表每一项至少包含：

- 目录名  
- 照片数量（采用 `photo_count_total`，文案如「共 N 张」）  
- 可选：子文件夹个数  

空状态：NAS 未连接 / 索引失败时的明确提示（不静默空白）。

### 4.3 数据来源

- Home **只消费 API 或打包进体验版的索引快照**，不在小程序内扫盘。
- 刷新：下拉刷新触发「重新拉取树」；是否触发服务端重扫由 API 决定。

## 5. 层级映射与导航需求

### 5.1 映射原则

NAS 相对路径 ↔ 小程序路由参数 **一一对应**：

```text
逻辑 path:  一起旅游啦/2026.9.25泉州之行
小程序：    /pages/album/album?path=<urlencode(逻辑 path)>
```

- `path` 为空或 `/` 表示根 `Dudu`。
- 禁止用易变的「数组下标」作为唯一身份；`path`（或内容哈希 + path）为稳定 id。

### 5.2 交互

1. Home：展示根下文件夹。  
2. 点击文件夹 → 进入该 path 的层级页。  
3. 层级页：上区为**子文件夹**（可再点下钻），下区为**本层文件列表**（仅元数据）。  
4. 返回：导航栈返回上一 path；支持展示面包屑（可选）。  
5. 本阶段点击照片文件 → 可 toast「后续加载」或进入空详情页，**不请求图片二进制**。

### 5.3 与 NAS 一致性

| 场景 | 期望 |
|------|------|
| NAS 改名/移动文件夹 | 下次索引后旧 path 404；前端提示「目录不存在」 |
| 仅增删照片 | 数量与文件列表更新；path 不变 |

## 6. 相片加载策略探讨（本阶段只讨论，不实现）

目标：**最大限度不损失相片质量**；同时遵守小程序包体、内存、域名与流量约束。

### 6.1 原则分层

| 层级 | 用途 | 画质要求 | 建议 |
|------|------|----------|------|
| L0 元数据 | 列表文件名、张数 | 无像素 | Phase 1 只做这层 |
| L1 缩略图 | 网格滚动 | 可有损 | 服务端生成短边 200–400px JPEG/WebP，**独立缓存文件**，永不覆盖原件 |
| L2 预览图 | 点开查看 | 接近屏显 | 长边对齐设备 CSS 像素×dpr（常见 1280–2048），有损质量可设 JPEG 85–92 或 WebP 质量等价 |
| L3 原图 | 「查看原图」/保存 | **比特级尽量保真** | 原格式字节流代理；HEIC 在部分安卓需服务端转 JPEG **仅用于显示副本**，NAS 原件不动 |

**结论草案：** 展示链路的有损只发生在 L1/L2 派生文件；L3 与 NAS 原件一致（容器允许范围内）。用户保存到手机相册应走 L3。

### 6.2 是否需要转成 WebP？

| 方案 | 优点 | 风险 / 成本 | 建议 |
|------|------|-------------|------|
| 原格式直出（JPEG/PNG） | 无二次编码损失（对已是 JPEG 的原件） | HEIC 兼容差；PNG 原图大 | L3 优先原格式 |
| **派生 WebP（仅 L1/L2）** | 同观感体积更小，省流量与解码时间 | 多一次有损；老基础库需确认 | **推荐用于缩略图/预览派生**，不替换 NAS 原件 |
| 全库转 WebP 覆盖原件 | — | **不可接受**（永久损画质/丢 HEIC 特性） | **禁止** |
| AVIF | 压缩更好 | 小程序端兼容与编码成本 | Phase 1+ 观望，不作默认 |

微信 `<image>` 对 WebP 支持较好（需以当前基础库为准做真机抽检）。  
**HEIC：** iPhone 源常见；建议 NAS 保留 HEIC；L2/L3 对不支持的端由服务端即时或缓存转 JPEG 显示副本。

### 6.3 「不损质量」的可操作定义

1. **存储侧零改写**：NAS 上文件禁止就地转码覆盖。  
2. **L3 传输**：HTTPS 原样字节；禁用网关强制改图（CDN 图片处理要对 original 路径关闭）。  
3. **派生图可重建**：L1/L2 可删可再生成；参数写入文件名或 sidecar（如 `._thumb_400.webp`）。  
4. **上传方向**（若未来支持）：默认 `original`；压缩需用户显式同意。

### 6.4 小程序本地存储怎么用？

| 能力 | 额度/特点 | 适用 |
|------|-----------|------|
| `wx.setStorage` / 同步 Storage | 单应用约 10MB 量级 | 仅路径、会话、最近浏览 path；**禁止存原图** |
| 临时文件 `downloadFile` → `tempFilePath` | 会话级，可能被清理 | 当次预览 |
| `wx.saveFile` / 用户文件目录 | 有上限，占用户空间 | 少量收藏缩略图；需配额策略与清理 |
| `wx.saveImageToPhotosAlbum` | 写入系统相册 | 用户主动保存原图的终点 |
| 分包 / 包内静态图 | 算包体积 | 仅 UI 图标，不放用户相册 |

**推荐策略（后续阶段）：**

- 本地：**索引元数据可缓存**；L1 缩略图用内存 + 有限磁盘 LRU；L3 不落长期本地，用完可删临时文件。  
- 权威仍在 NAS；小程序不做「第二图床」。

### 6.5 与 Phase 1 的边界

Phase 1 交付到「能点进目录看到文件名与数量」为止。  
§6 的选型作为 Phase 2 设计输入，实施前再开专项设计评审。

## 7. 非功能需求（Phase 1）

| 类别 | 要求 |
|------|------|
| 权限 | 相册 API 需登录或设备绑定；测试号阶段可放宽但仍不裸奔全网 |
| 只读 | 默认不对 NAS 写文件 |
| 隐私 | 路径与文件名含个人信息，日志脱敏；不把完整树提交到公开仓库 |
| 编码 | 全链路 UTF-8；注意 URL encode |
| 可观测 | 索引任务记录开始/结束时间、目录数、照片总数、失败路径 |

## 8. 验收标准（Phase 1 Done）

1. 文档化的 NAS 连接方式可复现；`/Volumes/home/Dudu` 可达（含 VPN 说明若启用）。
